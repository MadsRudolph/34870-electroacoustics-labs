What would you do?

Keep this open during the lab

Pull → edit → commit → push.

We work together on main. Agree who edits which files before you start. If Desktop says the branch is protected, ask Mads for the branch workflow.

GitHub→ pull →Your files→ commit →Local snapshot→ push →GitHub
  1. Start fresh. Select this repository and main in Desktop. Click Fetch origin, then Pull origin if offered. Fetch checks for changes; pull downloads them.
  2. Edit and save. Work inside the cloned folder in MATLAB, LTspice or your editor. Coordinate before editing a file someone else is using.
  3. Review and commit. In Changes, check the files you intend to share and inspect the differences. Add a clear summary, such as “Add Lab B reference measurement”, then click Commit to main.
  4. Push origin. This uploads your commits. If Desktop requires a pull first, pull and resolve any conflicts before retrying. Verify your commit on the repository website.
  5. Hand over. Tell the group what you changed and whether Overleaf needs a pull.
Saving ≠ committing ≠ sharing. Saving changes a file. Committing records a snapshot on your PC. Pushing shares committed snapshots through GitHub.

Reports in Overleaf

Open our Overleaf project ↗

Overleaf is a separate copy with manual GitHub sync. Arrange one sync owner and avoid editing the same report locally and in Overleaf at the same time.

  • Before editing in Overleaf: make sure earlier Overleaf edits have been pushed, then use its GitHub sync panel to pull the latest GitHub changes.
  • After editing in Overleaf: push its changes to GitHub. Everyone then fetches and pulls in Desktop.
  • After a PC edit: commit and push in Desktop, then pull from GitHub into Overleaf. If both copies changed, coordinate with Mads before syncing.

Ask Mads for the Overleaf project invitation. The main document is the relevant lab's report, for example Lab B/report/LabB_report.tex.

Small fixes, calmly

Something looks different?

“Repository not found”, 404, or a request to fork

Sign in with the account Mads invited and accept the invitation. Ask Mads to check your write access. Use the exact repository link below. Do not create a fork for this shared workflow.

My edits do not appear in Changes

Save the file in your editor. Confirm Desktop shows the right repository and that the edited file is inside its cloned folder, not a ZIP download or USB copy. Some temporary files are deliberately excluded by .gitignore.

I committed, but the others cannot see my work

Click Push origin, then check the repository website. A commit alone stays on your PC. Confirm you are on main.

Push failed, or Desktop asks me to pull first

Check your connection. Someone may have pushed since your last pull: fetch, pull, then push again. If a conflict appears, use the next item. If GitHub reports a file-size limit, ask Mads how to share that dataset; do not repeatedly retry the same push.

Merge conflict, or local edits block a pull

Keep your work. If local edits block pulling, review and commit them first. A conflict means Git needs help combining edits. Ask the teammate who edited that file or Mads to resolve it with you, then follow Desktop's resolution prompts. Do not discard changes, force-push, or pick a whole side just to dismiss the message.

MATLAB or LTspice does not run

Cloning downloads the files; it does not install lab software. Follow the relevant lab README and course instructions. For Lab B BEM, obtain BEM_FreeField.zip from DTU Learn and unpack into Lab B/bem/package/; it is not included in Git.

The lab PC has no internet

The Lab B README says to bring the MATLAB folder on a USB stick or laptop. Copy measurements back into your cloned repo's lab data folder afterwards, preserving originals and avoiding overwrites. Commit and push when online.

I use Linux

GitHub Desktop officially supports Windows and macOS. Ask Mads for a Linux setup; the instructions in this guide assume the official Desktop app.

What do these Git words mean?

Repository: project files plus their history. Clone: download a working copy with history. Commit: a named local snapshot. Push: upload commits. Fetch: check remote history. Pull: bring remote changes into your copy. Origin: our GitHub repository. Main: the shared branch we use.
